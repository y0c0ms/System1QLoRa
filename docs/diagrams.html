The 270M scorer is trained; the llama.cpp arm is not — it scores options already resident on the GPU. Both are measured on the same rows so the comparison is clean.

    Q --> ENC
    S --> ENC
    O --> ENC
    ENC --> M --> H --> P
    P --> T --> R

state, question and options all arrive at scoring time. The head emits one score per (question, state, option) sequence; softmax over the request's own option set yields a calibrated distribution.

The shipped corpus shares all 36 question strings between train and test; the SNI split does not. LoRA trains on 111 tasks whose categories are disjoint from the 39 test predicates — the first number that can separate generalisation from memorisation.

Every run is single-threaded on CPU at the documented memory constraint (batch 4, max_len 128 — see docs/FINDINGS.md), with the LoRA adapter checkpointed and resumable.
